## Quyết định đã chốt

1. Fact **simple upsert**, giữ trip_key cho source key đang hiện diện; stale accepted keys dọn đúng version. Không delete/reinsert toàn file cho rerun thông thường. Bỏ stable identity resurrection sau reject→reaccept vì không còn history để recover key.
2. Một classification table gọn theo batch/version; raw-exact và candidate hashes chỉ transient. Raw JSON không đi vào physical classification/Fact.
3. Exact dedup trong file vẫn giữ serialization cũ. Candidate cùng file chỉ diagnostic flag/count, không tự quarantine hay đổi warning/eligibility. Cross-file DUP-002/history runtime bỏ, limitation ghi rõ.
4. Fact/DQ normalize file text/checksum/schema qua metadata. Giữ natural unmapped codes, fees và timestamps để không mất phân tích. Analysis view derive bands/metadata; không thêm copy bảng rộng.
5. Date/Time/reference init một lần, xử lý ngày hợp lệ ngoài calendar rõ ràng. Không quét accepted mỗi batch để dựng Date.
6. Daily refresh aggregate toàn Fact của affected days old+new, kể cả file khác. Tháng phân tích theo pickup/dropoff, source month là lineage/audit.
7. Full historical audit ra khỏi mỗi batch nhưng vẫn có checkpoint/cuối backfill. Success/watermark sau tests/reconciliation/OLAP, cleanup sau SUCCESS.
8. Legacy archive/registry không còn runtime dependency mới, nhưng không xóa dữ liệu/bảng cũ trong Cụm 1 hay tự chạy migration.
